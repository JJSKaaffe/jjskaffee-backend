# ADR-0001: Aislar datos y delegar autenticación a un tercero

## Estado
Aceptado y validado con evidencia real (SPIKE-01 y SPIKE-03 ejecutados exitosamente)

## Criterios de evaluación
**Resumen:** Se buscaba determinar cómo garantizar que la información de cada cafetería cliente permanezca aislada de la de los demás, y si conviene construir la autenticación internamente o delegarla a un proveedor especializado.

**Detalles:**
- Nivel de seguridad demostrado en producción por el candidato.
- Costo por usuario activo o por mes.
- Facilidad de integración con el resto del sistema.
- Soporte nativo del concepto de "organización" o cliente separado (multi-tenant).

## Candidatos a considerar
**Resumen:** Se identificaron candidatos a partir de proveedores ampliamente usados en productos SaaS similares, además de la opción de desarrollo propio como punto de comparación.

**Candidatos:**
- Desarrollo propio de autenticación y control de acceso.
- Firebase Authentication.
- Auth0.
- Supabase Auth.

## Investigación y análisis de cada candidato

### Cumple/no cumple con los criterios y por qué
**Resumen:** El desarrollo propio no cumple el criterio de seguridad demostrada en producción sin experiencia especializada; los tres proveedores externos sí cumplen, con diferencias en costo y facilidad de integración.

- **Desarrollo propio:** No cumple — requiere experiencia especializada en criptografía y manejo de sesiones que el equipo no posee.
- **Firebase Authentication:** Cumple — nivel gratuito amplio (50.000 usuarios activos/mes), buena documentación, integración sencilla.
- **Auth0:** Cumple — robusto y flexible, con certificaciones adicionales (HIPAA, PCI-DSS), pero con costos más altos a partir de cierto volumen de usuarios.
- **Supabase Auth:** Cumple — económico y con base de datos relacional incluida, pero con menor trayectoria en el mercado que las otras dos opciones.

### Análisis de costos

**Desarrollo propio:**
- Licencias: no aplica.
- Capacitación: alta — requiere formación específica en seguridad y criptografía que el equipo no posee.
- Operación: el mantenimiento y la corrección de vulnerabilidades recaen completamente en el equipo interno, de forma indefinida.
- Medición: sin proveedor externo que absorba el costo, cualquier incidente de seguridad es asumido enteramente por el producto.

**Firebase Authentication:**
- Licencias: gratuito hasta 50.000 usuarios activos/mes; aproximadamente $275 USD/mes a 100.000 usuarios.
- Capacitación: mínima, documentación oficial extensa.
- Operación: soporte y mantenimiento a cargo de Google.
- Medición: costo proyectado de $0 para el volumen esperado en la fase inicial (20-50 cafeterías).

**Auth0:**
- Licencias: gratuito hasta 25.000 usuarios activos/mes; aproximadamente $1.750 USD/mes a 50.000 usuarios y $5.250 USD/mes a 100.000 usuarios.
- Capacitación: mínima, documentación oficial extensa.
- Operación: soporte y mantenimiento a cargo de Auth0, con mayor nivel de soporte empresarial disponible.
- Medición: costo significativamente más alto que Firebase para el mismo volumen de usuarios.

**Supabase Auth:**
- Licencias: gratuito en el plan inicial, con costo asociado al plan de hosting de base de datos elegido (a partir de aproximadamente $25 USD/mes).
- Capacitación: mínima.
- Operación: soporte y mantenimiento a cargo de Supabase.
- Medición: costo bajo, pero atado al mismo proveedor de base de datos.

### Análisis FODA

**Desarrollo propio:**
- Fortalezas: control total sobre el código y el comportamiento del sistema.
- Debilidades: alto riesgo de vulnerabilidades sin experiencia especializada; consume tiempo de desarrollo que compite con los módulos diferenciales del producto.
- Oportunidades: ninguna relevante frente a las alternativas externas.
- Amenazas: un error de seguridad podría exponer información financiera sensible de múltiples clientes.

**Firebase Authentication:**
- Fortalezas: nivel gratuito muy amplio, documentación madura, integración rápida.
- Debilidades: funciones empresariales avanzadas (SSO, SAML) requieren el nivel de pago superior (Identity Platform).
- Oportunidades: sinergia con Firebase Cloud Messaging para notificaciones (ver ADR-0011).
- Amenazas: dependencia del ecosistema de Google.

**Auth0:**
- Fortalezas: mayor cantidad de certificaciones de cumplimiento, robusto para necesidades empresariales.
- Debilidades: costo significativamente más alto a partir de volúmenes intermedios de usuarios.
- Oportunidades: útil si el producto migra a clientes empresariales grandes en el futuro.
- Amenazas: el costo podría no justificarse frente al volumen real de la fase inicial.

**Supabase Auth:**
- Fortalezas: integra autenticación y base de datos relacional en un mismo ecosistema.
- Debilidades: menor trayectoria en el mercado que Firebase o Auth0.
- Oportunidades: simplicidad si se decide usar Supabase como proveedor de base de datos.
- Amenazas: atarse a un proveedor único para dos capacidades distintas (auth y datos) aumenta el riesgo de dependencia.

### Opiniones y comentarios internos
**Resumen:** El equipo coincide en que el desarrollo propio de autenticación representa un riesgo desproporcionado frente al tiempo disponible y la experiencia del equipo.

- Del equipo: se prioriza reducir el riesgo de seguridad sobre el control total del código de autenticación.
- De otras partes interesadas: el aislamiento de datos entre cafeterías se identificó como el atributo de calidad de mayor prioridad para el rol Administrador (11 sobre 11 en la matriz de priorización).

### Opiniones y comentarios externos
**Resumen:** Se investigaron fuentes de mercado (comparativas de precios y capacidades de Firebase, Auth0 y Supabase) como parte del SPIKE-01.

- ¿Qué se está creando?: un producto B2B tipo SaaS, orientado a múltiples cafeterías clientes, de uso en producción, con arquitectura monolítica.
- ¿Cómo se evaluaron los candidatos?: mediante comparación de costos proyectados al volumen esperado (20-50 cafeterías) y revisión de documentación oficial de cada proveedor.
- ¿Por qué se eligió al ganador?: Firebase Authentication ofrece el mejor costo-beneficio para el volumen proyectado, sin necesitar las capacidades empresariales adicionales que justificarían el costo de Auth0.
- Sabiendo lo que se sabe ahora, la recomendación es no invertir tiempo en desarrollo propio de autenticación bajo ninguna circunstancia para este tipo de producto.

### Anécdotas
Ninguna registrada aún.

## Recomendación
**Resumen:** Delegar la autenticación y el aislamiento de sesión a Firebase Authentication, manteniendo el filtrado de datos por cafetería como responsabilidad interna del producto.

**Detalles:** Revisar esta decisión si el volumen de usuarios se acerca al límite del nivel gratuito o si se requieren capacidades empresariales no disponibles en el plan actual (ver resultado de SPIKE-01).

**Evidencia real de ejecución (SPIKE-01):** registro de usuario en 1.181ms, asignación de `id_cafeteria` vía custom claim en 427ms, generación de token en 1ms. **(SPIKE-03):** el aislamiento de datos se validó exitosamente con un usuario de aplicación limitado (no superusuario) y `FORCE ROW LEVEL SECURITY`, confirmando que una cafetería no puede acceder a datos de otra.
